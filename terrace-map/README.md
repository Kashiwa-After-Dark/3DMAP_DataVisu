# テラス拡大マップ・デモ

ルートヒストリーから独立した、地図の対象範囲・視点を確認するための静的デモ。

- URL: `/terrace-map/`
- 入口: ルートヒストリー上部のモード切替 → `TERRACE`。
- モデル: ユーザーが追加した `../3Dmodel/teras.glb`（約24.9MB）。元ファイルの複製・加工・上書きなし。
- 対象: `デッキ床`、ベンチ・植栽・階段・エスカレーターなどの名前付きパーツ。`駅` と `プラザ` は周辺表示で切替。
- `js/config.js`: モデル参照・対象名・補助モデルの非表示・位置校正の状態。
- `js/model.js`: GLB読み込みと対象／周辺の表示。
- `js/mapView.js`・`js/cameraFit.js`: 拡大視点・回転・ズーム・画面サイズ対応。
- `js/toolbar.js`: 2D/3D、ズーム、視点復帰、周辺表示、全画面操作。
- `js/index.js`: 起動・読み込み状態。
- `css/style.css`・`index.html`: この画面だけの見た目と構造。

既存のタイムスペースグラフや統計画面のHTML・CSS・JSには依存しない。Three.jsの版は既存と同じ0.166.1。アイコンはLucide。元の色・材質・パーツ名・変換を保持し、テラス画面内の照明で表示する。補助パス `rout` は非表示。対象名が不足する場合は空画面で成功扱いにせずエラーとする。

観察データは `backend/publicRouteApi.js` の読み取り専用APIを利用し、`PUBLIC_SURVEY_DATE`（現在 `2026-10-23`）と設定済みの対象ソースに一致する記録のみを取得する。元データ・API・対象日・ルート・観察メモ・他画面の集計は変更しない。春学期データへのフォールバックはしない。

## TRコードによる観察表示

- `js/observationData.js`: 既存APIクライアントの呼び出しと対象ソース判定。
- `js/observationModel.js`: 場所コードの取得、TR先頭一致、調査日と時間帯、欠損座標の処理。
- `js/observationPanel.js`: 一覧・詳細・時間帯／場所コードの選択、収納。
- `js/observationMarkers.js`: 実際の緯度経度による地図の点と選択。人は白、物は薄いオレンジ。

APIの正式な取得元は `placeCodes` 配列で、`TR`で始まるコードが1つでもある観察記録を1件として扱う。複数コードを持っていても重複表示せず、どのTRコードからでも絞り込める。`placeMeanings` 配列の説明も一覧選択肢・詳細に表示する。正式な配列が空なら場所名から補完しない。

旧形式の予備対応は `placeCode` / `place_code` / `locationCode` / `location_code` と `original` 内の同名項目、構造化 `place.code`、または `TR` コードで始まる `place` / `original.place`。半角・全角と大文字小文字を正規化する。日本語の「テラス」や説明文のTR文字列からは推測しない。明示された非TRコードは除外する。

2026-11-09の初回確認ではコード項目がなく対象0件だったが、作業中にユーザーがAPIへ `placeCodes` と `placeMeanings` を追加。再取得でTR対象172件（人172・物0）、座標あり136件・なし36件を確認した。時間帯別は18–20が33件、20–22が96件、22–24が43件。コードは `TR-00`、`TR-01`、`TR-04`、`TR-05`、`TR-06`、`TR-07`、`TR-08`、`TR-09`。残り288件はコードが未付与のため推測で追加しない。

全体は8軌跡・観察460件（人440・物20）のまま、ソースも `observations_people_2026-10-24.csv` と `observations_objects_2026-10-24.csv` のまま。対象日・件数・秘密情報・共有APIクライアントはこの作業では変更していない。

TRコードの全記録が対象で、GLBの仮の対象範囲から外れていてもコードだけで除外しない。座標なし・不正座標は一覧へ残し、地図上の点は作らない。点のXZは既存GLBの座標換算と同じ。高さは対象メッシュとの交点に1単位加算、交点なしは模式的な高さ9で表示する（実測高度ではない）。API自体の空状態・通信失敗も地図表示とは独立して扱う。手動再読み込みあり。
